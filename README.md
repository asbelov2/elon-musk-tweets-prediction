# TweetScope

Веб-приложение для статистического прогноза количества публикаций Илона Маска и сравнения модельных вероятностей с ценами покупки YES/NO на Polymarket. Интерфейс на русском. Сервер, браузерный код, модель, сборщики и тесты написаны на **TypeScript**: Node.js 24, Fastify, встроенный SQLite, Luxon, esbuild. Python и нативные сборочные инструменты не нужны.

## Запуск

Нужен **Node.js 24.19+ (ветка 24 LTS)** и npm. Версия закреплена в `.nvmrc`, допустимый диапазон — в `package.json`. Из каталога репозитория:

```bash
npm ci
npm run check
npm start
```

`npm run check` проверяет типы сервера, клиента и браузерных тестов, собирает приложение, выполняет unit/integration-тесты и проверку форматирования. Зависимости и integrity-хеши закреплены в `package-lock.json`; установка для воспроизводимости выполняется через `npm ci`.

`npm start` и `npm run dev` автоматически загружают `.env` из корня проекта. В нём можно задать `X_BEARER_TOKEN` без префикса `Bearer`. Файл необязателен и исключён из Git. Уже заданные переменные процесса имеют приоритет над `.env`. После изменения `.env` полностью перезапустите сервер и обновите страницу: hot reload не отслеживает этот файл.

Откройте приложение в браузере на порту 8000 машины, где запущен сервер. По умолчанию он слушает только `127.0.0.1`. Для доверенной облачной прокси можно задать `TWEETSCOPE_HOST=0.0.0.0`; авторизации в приложении нет, не выставляйте его напрямую в открытый интернет. `PORT` меняет порт, `TWEET_DB` — путь к базе (по умолчанию `data/tweets.sqlite3`).

Другие команды:

| Команда             | Назначение                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------- |
| `npm run dev`       | Сборка и наблюдение за сервером, рабочими потоками, браузерным TS и статическими файлами |

Для браузерных тестов используйте системный Chromium (автоматически обнаруживается `/usr/bin/chromium`), задайте `CHROMIUM_EXECUTABLE` или установите браузер командой `npx playwright install chromium`. E2E-сервер поднимается на порту 8011 с отдельной временной базой и без ключей X. Платные API эти тесты не вызывают.

Нажмите **«Посмотреть демо»**: создадутся 120 дней искусственной активности и искусственные стаканы. Демо физически отделено от реальной истории, всегда явно помечено и не подходит для ставок. После перезапуска история сохраняется в SQLite; процессы и автообновление страницы запускаются заново.

## Реальные данные

1. Основной источник — **XTracker**. Укажите ссылку на событие, откройте вкладку **API X / XTracker**, выберите XTracker и соберите историю. Токен X не нужен. После предпросмотра подтвердите сохранение. Нужны минимум 14 полных дней обучения, лучше 60–120. API X и CSV доступны как отдельная дополнительная история.
2. Загрузите событие по ссылке Polymarket. Gamma API возвращает правила и диапазоны; CLOB API — asks отдельно для YES и NO. Для истории XTracker также загружаются Post Counter и точные границы соответствующего трекинга. Они подставляются в форму в часовом поясе Нью-Йорка. Цены из карточки события и midpoint не используются как цена покупки.
3. Сверьте начало, конец и часовой пояс **с текстом правил рынка**. Для события из пользовательской ссылки живой Gamma API подтвердил период **13 октября 2026, 12:00 ET — 20 октября 2026, 12:00 ET**. Начальные даты в форме соответствуют ему, но при смене события требуется новая проверка. Дата создания события не используется как начало подсчёта.
4. Проверьте состав публикаций (ответы, репосты, цитаты), полноту источника и подтвердите правила. Для разных рынков состав может отличаться. XTracker хранится в отдельном наборе `xtracker`, API X/CSV — в `live`, демонстрация — в `demo`. Они не смешиваются. Переключатель «История для прогноза» выбирает реальный набор.
5. Задайте бюджет **на одну сторону одной позиции**, резерв расходов и запас к вероятности. Нажмите **«Рассчитать прогноз»**. При наличии ссылки котировки обновляются перед расчётом. Снимок рынка сохраняется в SQLite. Можно включить обновление котировок и расчёта каждую минуту, пока открыта вкладка. Полный экспорт истории автоматически не повторяется — его обновляйте отдельно. Post Counter и завершённые часы выбранного события обновляются перед каждым расчётом XTracker, включая автоматическое обновление раз в минуту.

### Импорт CSV

```csv
timestamp,count
2026-10-01T00:00:00Z,3
2026-10-01T01:00:00Z,0
2026-10-01T02:00:00Z,7
```

Каждая строка — количество засчитываемых публикаций в полном интервале `[timestamp, timestamp + 1 час)`. Время обязательно с UTC-смещением; после перевода в UTC оно должно совпадать с началом часа. Допустимы целые числа от 0 до 10 000. Нулевые часы указывайте явно. Отсутствие строки означает **неизвестное значение**, а не ноль. Незавершённые и будущие часы, дубликаты внутри файла и отрицательные значения отклоняются. Повторный импорт обновляет совпавшие часы; ошибочный файл отклоняется целиком. Лимит файла — 5 МБ.

Экспорт CSV содержит выбранную реальную историю (`xtracker` или `live`). Демо в него не попадает. Файл базы хранится локально и не добавляется в Git.

### Официальный API X

Добавьте **Bearer Token приложения** в секрет `X_BEARER_TOKEN` в настройках облачной среды. Значение не нужно вводить в чат, интерфейс программы или файлы репозитория. Для локального запуска допустима также существующая переменная `TWITTER_BEARER_TOKEN`. Интерфейс показывает только наличие ключа, не его значение. После применения настройки перезапустите сервер при необходимости.

Во вкладке **API X / XTracker** выберите официальный API и режим доступа:

- **Полный архив:** `/2/tweets/search/all`, запрос `from:elonmusk`, явные `start_time` / `end_time`, до 500 записей на страницу, обработка `meta.next_token`. Требует соответствующего тарифа X.
- **Лента:** lookup `/2/users/by/username/elonmusk`, затем `/2/users/{id}/tweets`, до 100 записей на страницу с `pagination_token`. Из-за ограничения последних публикаций лента принимается **только при достижении записи не позднее начала периода**. Если лимит не позволяет дойти до границы, сбор отклоняется без сохранения нулей. Выберите полный архив, более короткий период (не менее 15 дней для обучения) или CSV.

Типы определяются по `referenced_tweets`: `replied_to` / `retweeted` / `quoted`. Цитаты и обычные публикации включены; ответы и репосты управляются флажками. Ответы, содержащие цитату, остаются ответами для исключения. Сначала появляется предпросмотр, затем отдельное подтверждение полноты и правил. Удалённые публикации могут отсутствовать в API X, но учитываться источником разрешения — всегда сверяйте счётчик рынка.

Сбор использует лимиты и оплачиваемый объём вашего тарифа. Установлен предел 100 страниц на сбор. При ошибках авторизации, доступа, rate limit, частичном ответе или повторе пагинации результат не сохраняется. Автоматических повторных платных запросов после ошибки нет. Ключ отправляется только в HTTPS-заголовке `Authorization` на `api.x.com`; перенаправления отключены. В текущей среде ключ уже привязан. При проверке TypeScript-версии минимальный read-only запрос пользователя вернул HTTP 403: нужно проверить доступ и права приложения X. Выгрузка истории с этим доступом пока не подтверждена; повторные платные запросы после ошибки не выполнялись. Контрактные сценарии сборщика проходят тесты.

### XTracker: основной источник разрешения рынка

Используются публичные read-only endpoints из [официальной документации XTracker](https://xtracker.polymarket.com/docs):

- `GET /api/users/elonmusk?platform=X` — идентичность, число записей `_count.posts` и состояние синхронизации.
- `GET /api/users/elonmusk/trackings?platform=X&activeOnly=false` — все окна наблюдения. Рынок сопоставляется по точному slug в `marketLink`, а не по похожему названию. Неверный пользователь или неоднозначное окно отклоняются.
- `GET /api/users/elonmusk/posts?platform=X` — полный экспорт. Этот же endpoint используется кнопкой **Export Data** на сайте. Его контракт не требует пагинации или поля типа публикации.
- `GET /api/trackings/{id}?includeStats=true` — `stats.total` (Post Counter) и почасовые `stats.daily` с накопительными значениями.

Состав берётся **как у трекера**: публикации основной ленты, цитаты, учитываемые репосты, ответы основной ленты и удаления, сохранённые XTracker. Повторная фильтрация по `reply` / `repost` не применяется; флажки типов действуют только для API X. Программа не восстанавливает отсутствующие у источника удалённые посты и не считает незарегистрированные им community reposts самостоятельно.

Перед импортом проверяются:

1. Число уникальных `platformId` полного экспорта совпадает с `_count.posts`. При расхождении метаданные перечитываются один раз, чтобы отличить появление новой записи от усечения. Несогласованный результат не импортируется. Предел — 100 000 записей.
2. Все записи относятся к нужному пользователю; один ID с разными датами отклоняется. Идентичные дубликаты не считаются дважды.
3. Сумма публикаций выбранного события и каждый завершённый час совпадают с Post Counter и почасовыми значениями. Проверяются шаг в час, непрерывность, границы и накопительная сумма.
4. Нулевые часы создаются только внутри реальных окон наблюдения XTracker. Пробелы между окнами не импортируются и не становятся нулями. В модели они остаются неизвестными.

Предпросмотр показывает результат сверки и счётчик. После явного подтверждения часы и отчёт импорта сохраняются атомарно; API X/CSV не перезаписываются. Отчёты сохраняются в метаданных SQLite (`tracker:import:{slug}`), а обновления текущего счётчика — отдельно (`tracker:{slug}`).

Перед прогнозом выбранного рынка Post Counter запрашивается заново. Он используется как уже наблюдённое число публикаций, **включая текущий неполный час**. Модель прогнозирует оставшуюся долю часа и дальнейшее время; граница прогноза не откатывается к началу часа. Окно должно точно совпадать с окном трекинга. Окончание вида `15:59:59` нормализуется к исключительной границе `16:00:00`. Для отдельного дня очистите ссылку на рынок.

Свежий HTTP-ответ не доказывает свежесть данных. Проверяются `lastSync` и `lastSyncError`: если последняя успешная синхронизация старше 3 часов или ошибка новее успеха, счётчик и прогноз показываются с предупреждением, а сигналы покупки отключаются. Несогласованные суммы, неизвестная схема или недоступный API дают ошибку; старый сохранённый счётчик не используется как незаметная замена.

Для рынков с разрешением по Post Counter положительный сигнал требует истории XTracker и успешной сверки. Один флажок подтверждения правил не делает историю API X/CSV эквивалентной источнику разрешения.

При живой проверке полный экспорт и счётчик события совпали. Сам XTracker при этом сообщал об ошибке синхронизации — блокировка сигналов была проверена на реальных данных. Доступность и схема внешнего API могут изменяться.

## Модель

- До 120 **полных локальных дней**, учёт 23/25-часовых дней при переводе часов. Старые наблюдения получают экспоненциально меньший вес, период полураспада 21 день.
- Часовой профиль для каждого дня недели со сглаживанием к общему профилю часа. Разброс дневной интенсивности оценивается по дневным суммам.
- Gamma–Poisson: общий случайный множитель активности внутри будущего дня учитывает сверхдисперсию и корреляцию часов; общий множитель неопределённости интенсивности связывает будущие дни. Параметры оцениваются методом моментов; это практическая эвристическая модель, а не полноценный байесовский posterior.
- 20 000 воспроизводимых сценариев. Для XTracker известный Post Counter прибавляется к прогнозу остатка текущего часа и последующего периода; для дополнительной истории без трекинга используются завершённые часы. Возвращаются среднее, медиана, 10-й и 90-й перцентили, гистограмма и вероятности диапазонов. Интервал — прогнозный **по модели**, его фактическое покрытие может отличаться от 80%.
- Пошаговый бэктест до 14 последних полных дней: для каждого дня обучение идёт только на более ранних днях. Показываются MAE и доля попаданий в интервал 80%. Он проверяет суточный счётчик, **не доходность торговли**. При ровно 14 днях обучения бэктест ещё не имеет проверочных дней.

Можно прогнозировать отдельный день: выберите дату в дополнительных настройках периода. Для прогноза без рыночных позиций очистите ссылку события. Границы периода должны совпадать с целым часом UTC; горизонт ограничен 31 днём.

Модель не учитывает новости и содержание публикаций, удаления и изменения правил источника, не корректирует интенсивность остатка дня по уже наблюдаемому внутридневному темпу. Любой из этих факторов может существенно изменить итог. Погрешность Монте-Карло намного меньше потенциальной ошибки модели и не является мерой достоверности самой модели.

## Расчёт позиций

Покупка проходит по asks от дешёвых к дорогим с учётом объёма. Бюджет включает резерв расходов. Для рассчитанного числа акций `q`, стоимости покупки `C`, резерва `F` и модельной вероятности выигрыша `p`:

```text
EV = p × q − C − F
ROI = EV / (C + F)
Edge = p − (C + F) / q
Осторожный EV = max(0, p − запас_в_пп / 100) × q − C − F
```

Вероятность NO — дополнение к вероятности YES; стаканы у них разные. Выплата по одной выигравшей акции считается равной $1, проигравшей — $0. Резерв — оценка расходов пользователем, **не фактическая формула комиссий Polymarket**. Флаг включённых комиссий рынка показывается предупреждением. Сверьте тариф, исполнение, округления и дополнительные расходы перед сделкой.

Сигнал `+EV с запасом` появляется, только если:

- подтверждены правила и полнота истории; для рынка Post Counter выбрана сверенная история XTracker и источник не сообщает о проблеме синхронизации;
- последний учтённый час не старше 3 часов, последний полный день обучения не старше 72 часов;
- рынок принимает ордера, стакан не старше 120 секунд;
- asks покрывают не меньше 95% бюджета;
- осторожный EV положителен.

При неполном исполнении EV относится только к доступному объёму; неиспользованные деньги не считаются потерей. Запас — выбранный сценарий осторожности, не статистическая граница вероятности. Позиции одного события зависимы; программа **не оптимизирует портфель**, не складывайте их как независимые ставки. Положительный EV не гарантирует прибыль.

## Проверки и API

```bash
npm run check
npm run test:e2e
```

Параметры обучения сравниваются с сохранённым эталоном прежней модели для UTC и Нью-Йорка с относительным допуском 10⁻¹². Новые воспроизводимые генераторы Mulberry32 / Marsaglia–Tsang / Hörmann PTRS проверяются по моментам Gamma и Poisson. Поток случайных чисел отличается от прежнего NumPy: отдельные сценарии и округлённые прогнозы могут немного отличаться, математическая модель сохранена. Расчёт работает в ограниченных worker_threads и не блокирует HTTP-сервер. Тесты также проверяют математику Gamma–Poisson, отсутствие утечки будущего, уже учтённые публикации, покрытие часов, DST, атомарность CSV, раздельное хранение демо, стаканы, YES/NO, расходы, отключение сигналов и полный сценарий приложения. Статические страницы и API проверены в настоящем Chromium на desktop и мобильной ширине. UI не загружает скрипты и шрифты с внешних CDN.

API документирован на `/api/docs`:

| Метод | Путь                   | Назначение                                                        |
| ----- | ---------------------- | ----------------------------------------------------------------- |
| GET   | `/api/health`          | Проверка процесса                                                 |
| GET   | `/api/status`          | Покрытие истории, отдельно demo/live                              |
| POST  | `/api/import`          | JSON `content`, `coverage_confirmed` с CSV                        |
| GET   | `/api/export`          | Реальная почасовая история CSV                                    |
| POST  | `/api/collect`         | Предпросмотр API X или XTracker (`source`, `mode`, `days`, флаги) |
| POST  | `/api/collect/confirm` | Подтверждение полноты и сохранение                                |
| GET   | `/api/event?url=…`     | Событие и стаканы, сохранение снимка                              |
| POST  | `/api/demo`            | Генерация отдельного демо-набора                                  |
| GET   | `/api/xtracker?url=…`  | Post Counter, точный период и состояние синхронизации             |
| POST  | `/api/analyze`         | Прогноз и оценка загруженного снимка рынка                        |

`/api/analyze` не обновляет котировки: внешний клиент сначала вызывает `/api/event`, иначе стаканы могут быть устаревшими. При `dataset=xtracker` и выбранном событии этот endpoint сам обновляет Post Counter. По умолчанию анализ и сбор используют XTracker; для дополнительной истории явно задайте `dataset=live` или `source=x`. JSON-ошибки источников показываются пользователю; на реальные цены не подставляются демо-значения.

## Облачная среда

Работайте в существующем checkout `/workspace/elon-musk-tweets-prediction`: отдельный Git worktree для обычной задачи не нужен. Для каждой новой машины/процесса запускайте сервер заново; публикация среды не сохраняет живой процесс. Инструкции установки и старта сохранены также в черновик конфигурации облачной среды и используют только Node.js/npm. Shell-обёртки `bash scripts/setup.sh` и `bash scripts/start.sh` сохранены для совместимости.

Нужен HTTPS-доступ к `gamma-api.polymarket.com`, `clob.polymarket.com`, `xtracker.polymarket.com`; `polymarket.com` — для чтения страницы правил. Эти домены добавлены в черновик разрешённых направлений. Первые запросы отклонялись сетевым прокси (403); после применения настроек удалось проверить реальное событие, все 26 диапазонов и стаканы открытых рынков. Для недоступных/закрытых токенов цены не подставляются. Доступность в новой опубликованной машине ещё не проверялась. Зависимости устанавливаются из npm с проверкой integrity-хешей lock-файла. HTTP-клиент учитывает стандартные HTTPS_PROXY/HTTP_PROXY/NO_PROXY через Undici и не отключает проверку TLS. Демо и CSV работают без доступа к Polymarket/XTracker.

Секрет `X_BEARER_TOKEN` объявлен в черновике, назначение — `api.x.com`; этот домен также добавлен к разрешённым направлениям. Для нового окружения задайте значение в защищённых настройках, сохраните и опубликуйте конфигурацию. В текущей среде привязка уже существует — повторно создавать секрет не требуется.

Остаётся устранить отказ HTTP 403 со стороны API X и сверить реальную историю. Для указанного рынка правила также учитывают удалённые публикации, успевшие попасть в трекер, и отдельные ответы в основной ленте, но исключают неучтённые трекером community reposts. Простое исключение всех replies в API X **не гарантирует точного совпадения с Post Counter**; используйте подтверждение правил только после сверки. Приложение не отправляет ордера, не запрашивает приватный ключ и не подключает кошелёк.
