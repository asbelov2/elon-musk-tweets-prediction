# TweetScope

Веб-приложение для статистического прогноза количества публикаций Илона Маска и сравнения модельных вероятностей с ценами покупки YES/NO на Polymarket. Интерфейс на русском, Python/FastAPI, NumPy, SQLite, HTML/CSS/JavaScript без внешних CDN.

## Запуск

Нужен Python 3.12+ (проверено на 3.12.14). Из каталога репозитория:

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

Откройте браузер на порту 8000 машины, где запущен сервер. По умолчанию сервер слушает только `127.0.0.1`. Для доверенной облачной прокси можно задать `TWEETSCOPE_HOST=0.0.0.0`; в приложении нет авторизации, не публикуйте его напрямую в открытый интернет. `PORT` меняет порт. `TWEET_DB` меняет путь к SQLite (по умолчанию `data/tweets.sqlite3`). Эти параметры не являются секретами.

Нажмите **«Посмотреть демо»**: создадутся 120 дней искусственной активности и искусственные стаканы. Демо хранится отдельно от реальной истории и всегда явно помечено. Цены и результаты демо нельзя использовать для ставок. После перезапуска сервера история сохраняется в SQLite; процессы и автообновление страницы нужно запускать заново.

Установка использует полный `requirements.lock` с проверкой SHA-256. Обновлять зависимости следует отдельно, перегенерировав lock-файл и повторно выполнив проверки. `requirements.txt` содержит прямые зависимости.

## Реальные данные

1. Загрузите CSV или воспользуйтесь вкладкой **API X / XTracker**. Нужны минимум 14 полностью покрытых дней до прогнозируемого периода, лучше 60–120 дней. Для текущего рынка нужны все завершённые часы с начала его периода.
2. Загрузите событие по ссылке Polymarket. Gamma API возвращает правила и диапазоны; CLOB API — доступные предложения продажи отдельно для YES и NO. Цены из карточки события и midpoint не используются как цена покупки.
3. Сверьте начало, конец и часовой пояс **с текстом правил рынка**. Для события из пользовательской ссылки живой Gamma API подтвердил период **13 октября 2026, 12:00 ET — 20 октября 2026, 12:00 ET**. Начальные даты в форме соответствуют ему, но при смене события требуется новая проверка. Дата создания события не используется как начало подсчёта.
4. Проверьте состав публикаций (ответы, репосты, цитаты), полноту источника и подтвердите правила. Для разных рынков состав может отличаться. Не смешивайте историю с разными правилами подсчёта: используйте отдельную базу через `TWEET_DB`.
5. Задайте бюджет **на одну сторону одной позиции**, резерв расходов и запас к вероятности. Нажмите **«Рассчитать прогноз»**. При наличии ссылки котировки обновляются перед расчётом. Снимок рынка сохраняется в SQLite. Можно включить обновление котировок и расчёта каждую минуту, пока открыта вкладка. Сбор истории при этом автоматически не повторяется — её нужно обновлять отдельно.

### Импорт CSV

```csv
timestamp,count
2026-10-01T00:00:00Z,3
2026-10-01T01:00:00Z,0
2026-10-01T02:00:00Z,7
```

Каждая строка — количество засчитываемых публикаций в полном интервале `[timestamp, timestamp + 1 час)`. Время обязательно с UTC-смещением; после перевода в UTC оно должно совпадать с началом часа. Допустимы целые числа от 0 до 10 000. Нулевые часы указывайте явно. Отсутствие строки означает **неизвестное значение**, а не ноль. Незавершённые и будущие часы, дубликаты внутри файла и отрицательные значения отклоняются. Повторный импорт обновляет совпавшие часы; ошибочный файл отклоняется целиком. Лимит файла — 5 МБ.

Экспорт CSV содержит только реальную историю. Демо в него не попадает. Файл базы хранится локально и не добавляется в Git.

### Официальный API X

Добавьте **Bearer Token приложения** в секрет `X_BEARER_TOKEN` в настройках облачной среды. Значение не нужно вводить в чат, интерфейс программы или файлы репозитория. Для локального запуска допустима также существующая переменная `TWITTER_BEARER_TOKEN`. Интерфейс показывает только наличие ключа, не его значение. После применения настройки перезапустите сервер при необходимости.

Во вкладке **API X / XTracker** выберите официальный API и режим доступа:

- **Полный архив:** `/2/tweets/search/all`, запрос `from:elonmusk`, явные `start_time` / `end_time`, до 500 записей на страницу, обработка `meta.next_token`. Требует соответствующего тарифа X.
- **Лента:** lookup `/2/users/by/username/elonmusk`, затем `/2/users/{id}/tweets`, до 100 записей на страницу с `pagination_token`. Из-за ограничения последних публикаций лента принимается **только при достижении записи не позднее начала периода**. Если лимит не позволяет дойти до границы, сбор отклоняется без сохранения нулей. Выберите полный архив, более короткий период (не менее 15 дней для обучения) или CSV.

Типы определяются по `referenced_tweets`: `replied_to` / `retweeted` / `quoted`. Цитаты и обычные публикации включены; ответы и репосты управляются флажками. Ответы, содержащие цитату, остаются ответами для исключения. Сначала появляется предпросмотр, затем отдельное подтверждение полноты и правил. Удалённые публикации могут отсутствовать в API X, но учитываться источником разрешения — всегда сверяйте счётчик рынка.

Сбор использует лимиты и оплачиваемый объём вашего тарифа. Установлен предел 100 страниц на сбор. При ошибках авторизации, доступа, rate limit, частичном ответе или повторе пагинации результат не сохраняется. Автоматических повторных платных запросов после ошибки нет. Ключ отправляется только в HTTPS-заголовке `Authorization` на `api.x.com`; перенаправления отключены. В текущем runtime ключ ещё не задан: интеграция проверена контрактными тестами, живой запрос с авторизацией остаётся непроверенным.

### Публичный сборщик XTracker

Адаптер делает read-only запросы `GET https://xtracker.polymarket.com/api/users/elonmusk/posts` с `startDate`, `endDate`, `page`, `limit` и при наличии `cursor`. Поддерживаются массив `data` или `data.posts`, пагинация `pagination.totalPages` / `hasMore` / `nextCursor`, поля `id` / `platformId`, `createdAt` / `created_at`, `type` / `postType`. Распознаются обычные публикации, цитаты, ответы и репосты. Дубликаты ID удаляются. Повторяющиеся страницы, неизвестные типы, неподдерживаемая схема, пустая история и превышение 100 страниц дают явную ошибку.

Это **экспериментальный адаптер**, а не гарантированный контракт XTracker. После применения сетевых настроек живой API стал доступен: текущий ответ `success/data` не содержит типов публикаций и метаданных пагинации и игнорирует `limit`/`page`. Поэтому этот формат приложение **намеренно отклоняет**. Используйте официальный API X либо CSV. Контрактные тесты адаптера проверяют поддерживаемую схему, а не подтверждают совместимость с текущим XTracker.

Сначала показывается предпросмотр сбора. Нулевые часы создаются и сохраняются только после отдельного подтверждения пользователем полноты всего интервала и состава публикаций. Предпросмотр истекает через 30 минут. Даже успешная пагинация сама по себе не доказывает полноту источника: сверяйте начало истории и текущий счётчик с официальным источником разрешения рынка. По умолчанию ответы исключены, репосты включены — это настройки, а не утверждение о правилах указанного события. Цитаты включены всегда.

Для публичных API Polymarket и XTracker ключ не нужен. Официальный API X требует Bearer Token. Кошелёк и подпись не нужны ни одному сборщику.

## Модель

- До 120 **полных локальных дней**, учёт 23/25-часовых дней при переводе часов. Старые наблюдения получают экспоненциально меньший вес, период полураспада 21 день.
- Часовой профиль для каждого дня недели со сглаживанием к общему профилю часа. Разброс дневной интенсивности оценивается по дневным суммам.
- Gamma–Poisson: общий случайный множитель активности внутри будущего дня учитывает сверхдисперсию и корреляцию часов; общий множитель неопределённости интенсивности связывает будущие дни. Параметры оцениваются методом моментов; это практическая эвристическая модель, а не полноценный байесовский posterior.
- 20 000 воспроизводимых сценариев. Известное количество с начала рынка прибавляется к прогнозу оставшихся часов, включая задержку поступления данных. Возвращаются среднее, медиана, 10-й и 90-й перцентили, гистограмма и вероятности диапазонов. Интервал — прогнозный **по модели**, его фактическое покрытие может отличаться от 80%.
- Пошаговый бэктест до 14 последних полных дней: для каждого дня обучение идёт только на более ранних днях. Показываются MAE и доля попаданий в интервал 80%. Он проверяет суточный счётчик, **не доходность торговли**. При ровно 14 днях обучения бэктест ещё не имеет проверочных дней.

Можно прогнозировать отдельный день: выберите дату в дополнительных настройках периода. Для прогноза без рыночных позиций очистите ссылку события. Границы периода должны совпадать с целым часом UTC; горизонт ограничен 31 днём.

Модель не учитывает новости и содержание публикаций, удаления и изменения правил источника, не корректирует интенсивность остатка дня по уже наблюдаемому внутридневному темпу. Любой из этих факторов может существенно изменить итог. Погрешность Монте-Карло намного меньше потенциальной ошибки модели и не является мерой достоверности самой модели.

## Расчёт позиций

Покупка проходит по asks от дешёвых к дорогим с учётом объёма. Бюджет включает резерв расходов. Для рассчитанного числа акций `q`, стоимости покупки `C`, резерва `F` и модельной вероятности выигрыша `p`:

```text
EV = p × q − C − F
ROI = EV / (C + F)
Edge = p − (C + F) / q
Осторожный EV = max(0, p − запас_в_пп / 100) × q − C − F
```

Вероятность NO — дополнение к вероятности YES; стаканы у них разные. Выплата по одной выигравшей акции считается равной $1, проигравшей — $0. Резерв — оценка расходов пользователем, **не фактическая формула комиссий Polymarket**. Флаг включённых комиссий рынка показывается предупреждением. Сверьте тариф, исполнение, округления и дополнительные расходы перед сделкой.

Сигнал `+EV с запасом` появляется, только если:

- подтверждены правила и полнота истории;
- последний учтённый час не старше 3 часов, последний полный день обучения не старше 72 часов;
- рынок принимает ордера, стакан не старше 120 секунд;
- asks покрывают не меньше 95% бюджета;
- осторожный EV положителен.

При неполном исполнении EV относится только к доступному объёму; неиспользованные деньги не считаются потерей. Запас — выбранный сценарий осторожности, не статистическая граница вероятности. Позиции одного события зависимы; программа **не оптимизирует портфель**, не складывайте их как независимые ставки. Положительный EV не гарантирует прибыль.

## Проверки и API

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check app/static/app.js  # необязательно, если Node.js установлен
```

Тесты проверяют математику Gamma–Poisson, отсутствие утечки будущего, уже учтённые публикации, покрытие часов, DST, атомарность CSV, раздельное хранение демо, стаканы, YES/NO, расходы, отключение сигналов и полный сценарий приложения. Статические страницы и API проверены в настоящем Chromium на desktop и мобильной ширине. UI не загружает скрипты и шрифты с внешних CDN.

API документирован на `/api/docs`:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка процесса |
| GET | `/api/status` | Покрытие истории, отдельно demo/live |
| POST | `/api/import` | JSON `content`, `coverage_confirmed` с CSV |
| GET | `/api/export` | Реальная почасовая история CSV |
| POST | `/api/collect` | Предпросмотр API X или XTracker (`source`, `mode`, `days`, флаги) |
| POST | `/api/collect/confirm` | Подтверждение полноты и сохранение |
| GET | `/api/event?url=…` | Событие и стаканы, сохранение снимка |
| POST | `/api/demo` | Генерация отдельного демо-набора |
| POST | `/api/analyze` | Прогноз и оценка загруженного снимка рынка |

`/api/analyze` сам не делает сетевых запросов: внешний клиент должен сначала вызвать `/api/event`, иначе котировки могут быть устаревшими и сигналы отключатся. JSON-ошибки источников показываются пользователю; на реальные цены не подставляются демо-значения.

## Облачная среда

Работайте в существующем checkout `/workspace/elon-musk-tweets-prediction`: отдельный Git worktree для обычной задачи не нужен. Для каждой новой машины/процесса запускайте сервер заново; публикация среды не сохраняет живой процесс. Инструкции установки и старта сохранены также в черновик конфигурации облачной среды.

Нужен HTTPS-доступ к `gamma-api.polymarket.com`, `clob.polymarket.com`, `xtracker.polymarket.com`; `polymarket.com` — для чтения страницы правил. Эти домены добавлены в черновик разрешённых направлений. Первые запросы отклонялись сетевым прокси (403); после применения настроек удалось проверить реальное событие, все 26 диапазонов и стаканы открытых рынков. Для недоступных/закрытых токенов цены не подставляются. Доступность в новой опубликованной машине ещё не проверялась. Зависимости из PyPI устанавливаются успешно с проверкой хешей. Демо и CSV работают без доступа к Polymarket/XTracker.

Секрет `X_BEARER_TOKEN` объявлен в черновике, назначение — `api.x.com`; этот домен также добавлен к разрешённым направлениям. Введите значение в защищённых настройках среды, сохраните и опубликуйте конфигурацию. Само объявление секрета не задаёт ключ.

Остаётся проверить авторизацию и тариф X после добавления токена и сверить реальную историю. Для указанного рынка правила также учитывают удалённые публикации, успевшие попасть в трекер, и отдельные ответы в основной ленте, но исключают неучтённые трекером community reposts. Простое исключение всех replies в API X **не гарантирует точного совпадения с Post Counter**; используйте подтверждение правил только после сверки. Приложение не отправляет ордера, не запрашивает приватный ключ и не подключает кошелёк.
